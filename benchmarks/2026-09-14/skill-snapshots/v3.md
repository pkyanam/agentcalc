# agentcalc

Requires shell access and an installed `agentcalc` binary. Use `AGENTCALC_BIN` if configured, otherwise `agentcalc` on PATH or the absolute path in a Local installation section. No agent-specific skill directory is required.

For one calculation use `eval 'EXPR'`, `exact 'NUMBER OP NUMBER'`, `stats NUMBERS...`, or `convert VALUE FROM TO`. Quote expressions; exact operators need surrounding spaces. Core results use float64; exact returns reduced `fraction` and a decimal rounded to 30 places. Constants: `pi`, `e`, `tau`; powers: `^` or `**`; combinations: `choose(n,k)`. Angles are radians.

For several independent calculations, use one collected batch instead of separate processes and JSON reshaping:

```sh
agentcalc batch --collect --text <<'JSONL'
{"id":"growth","command":"eval","expr":"1000*(1+0.05/12)^24"}
{"id":"fraction","command":"exact","expr":"0.1 + 0.2","select":"fraction"}
{"id":"root","command":"root","expr":"cos(x)-x","lower":0,"upper":1}
{"id":"solution","command":"matrix","op":"solve","a":[[2,1],[1,-1]],"b":[5,1]}
JSONL
```

Each nonempty string `id` becomes an output key. Duplicate IDs or any failed request produce an error, never a partial success. `select` picks a result object field. Other batch fields: convert `value,from,to`; stats `values`; matrix `op,a,b` (solve accepts flat b; omit b for determinant/inverse/transpose); integrate `expr,lower,upper`; derivative `expr,x`. Numerical calculus is approximate and needs smooth functions; roots need a continuous sign-changing bracket.

For CSV (header required) or a JSON array of objects, use native named table queries. Put queries in a file with `--query-file PATH` or inline:

```sh
agentcalc table --input sales.csv --query '{"stats":{"op":"stats","column":"revenue","fields":["count","sum","mean","median","sample_stddev","p25","p75"]},"paid_totals":{"op":"sum","column":"revenue","group_by":"region","where":{"status":"paid"}},"top_ids":{"op":"values","column":"id","sort":[{"column":"revenue","desc":true},{"column":"id"}],"limit":5},"unit_price":{"op":"ratio","numerator":"revenue","denominator":"units"}}' --text
```

`fields` selects stats result keys; `where` is equality filtering; filters, sort, and limit apply before aggregation. Prefer these native operations to custom Python. Use Python/Node adapters for transformations beyond this query vocabulary; they execute trusted local code, not a sandbox.

Normal output is `{"ok":true,"result":...}`; `--text` prints the result directly. Errors have `ok:false` and `error`; exit codes are 0 success, 1 calculation/input/runtime, 2 usage. Read [the command reference](references/commands.md) only for additional functions, formats, or limits. Keep answers grounded in tool output.
